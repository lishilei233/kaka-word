### TODO-013：统一并优化 App 整体 UI 风格

- 类型：ui
- 优先级：P2
- 状态：待分析
- 需求描述：对 iOS App 的整体 UI 风格进行系统性调整和优化，使主要页面、公共组件与交互状态具有统一、清晰且有辨识度的视觉语言；所有 Sheet 应使用一致的 UI 风格和交互规范。
- 简要分析：
  - 用户事实：本次目标是整体 UI 风格调整优化，不只针对某一个页面或单一组件。
  - 用户补充事实（2026-09-07）：需要统一 App 内 Sheet 的 UI 风格。
  - 初步分析：现有规范将产品定位为“英语学习手账”，并已提供纸张背景、语义色、字体、卡片、按钮、Header 与 Sheet 等公共约定；实施前应先盘点各页面与规范的偏差，再确定统一设计基线，避免逐页零散修改。
  - 初步分析：设置页、会员购买页、“我的单词”和“听音找词”等局部页面此前已分别优化，本条应在保留已验证业务流程的基础上统一全局视觉，不重复改变已经稳定的功能逻辑。
  - 初步分析：Sheet 统一不应只处理背景和圆角，还需盘点标题区、关闭或完成操作、拖拽指示器、内边距、滚动行为、按钮层级、尺寸档位以及加载、空白、错误和危险操作等状态，形成可复用的共同规范。
  - 初步分析：现有 Sheet 至少涉及会员购买、单词详情、候选确认、练习提示和音色选择等不同用途；内容可以保留各自的信息结构，但同类控件和反馈应保持一致。
  - 待确认：尚未提供新的整体视觉参考、期望保留或替换的“英语学习手账”方向，以及首页、识别结果、历史、练习、设置等页面的实施优先级。
- 影响范围：
  - iOS 全局主题与公共组件，包括语义色、字体层级、间距、圆角、描边、阴影、纸张纹理、按钮、卡片、Header、Sheet 和状态反馈。
  - App 内各类 Sheet，包括但不限于会员购买、单词详情、识别候选确认、练习说明和设置项选择；具体清单应在技术分析阶段通过代码盘点确认。
  - iOS 主要用户流程，包括首次使用、首页、拍摄入口、识别过程与结果、历史和单词详情、学习练习、设置及会员相关页面。
  - 相机取景等沉浸式深色场景可继续作为视觉例外，但其控制区、返回方式和状态反馈仍需与全局交互语言协调。
  - 默认不包含服务端业务、识别算法、StoreKit 规则、数据模型或导航信息架构调整；若视觉方案要求改变交互流程，应另行确认范围。
- 验收标准：
  - 形成明确且可复用的整体视觉基线，主要页面不再出现相互冲突的颜色、字体、间距、圆角、图标、背景或组件样式。
  - 首页、识别、结果、历史、练习、设置和会员等主要流程的页面层级、主要操作、次要操作及状态反馈保持一致且易于识别。
  - 公共按钮、卡片、Header 和 Sheet 优先复用统一组件与语义色，页面不重复维护功能相同但视觉不同的实现。
  - 所有纳入范围的 Sheet 在背景、标题区、关闭或完成入口、内容边距、按钮层级、滚动与尺寸策略上遵循同一套明确规范；不同业务内容仍保持适合其任务的信息结构。
  - Sheet 的加载、空白、错误、禁用、选中、成功确认和危险操作状态具有一致且可理解的表现，关闭方式和主要操作不会因页面不同而产生无理由的差异。
  - 会员购买、单词详情、候选确认、练习提示和音色选择等现有 Sheet 完成视觉回归，原有业务操作、数据保存和关闭行为不受破坏。
  - 加载、空状态、错误、禁用、选中、成功和危险操作不能只依赖颜色表达，并保留清晰的反馈与可恢复路径。
  - 小屏与大屏、长文案、Dynamic Type、VoiceOver 和 Reduce Motion 下内容可读、操作可达，无明显截断、遮挡或布局跳动。
  - UI 调整不破坏现有导航、识别、历史、练习、购买、恢复购买及会员状态刷新等业务行为。
  - 最终实现同步更新 `docs/UI_GUIDELINES.md`，使规范与实际公共组件及页面表现一致。
