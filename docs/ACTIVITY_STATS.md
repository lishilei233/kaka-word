# 用户活跃统计

统计对象是现有服务端安装标识，界面使用“设备数”。它不是 App Store 下载量，也不能跨设备识别同一个人。所有日期按 Asia/Shanghai 计算。

## 指标口径

- 访问活跃设备：所选期间至少一次进入前台。跨午夜持续在前台时补记新的一天，不增加打开次数。
- App 打开：每次冷启动，或进入后台满 30 分钟后再次进入前台；短暂切后台和系统弹窗不增加打开次数。
- 学习活跃设备：成功识别、首次确认一道听音找词题（找到或揭晓）、主动播放单词并实际开始播放，任一行为发生即计入。
- 学习参与率：所选期间访问设备与学习设备的交集 / 访问设备。学习活跃可以包含未上报前台事件的旧客户端，故不能直接用全部学习设备数除以访问设备数。
- 近 7／30 天活跃：截至所选结束日期的完整滚动窗口内去重，不相加每日设备数。不限时间时截至今天。
- 设备活跃天数：所选期间有任一已记录行为的日期数；学习天数仅含学习行为。最近活跃是全历史中最近的已知行为时间，不受所选时间范围限制；仅有历史识别覆盖的设备显示日期，不把汇总日的占位时间当成精确行为时间。
- 听音找词进入：进入页面时一次，空状态也记录；开始轮数：首次呈现非空、可答题的一轮；恢复同一轮不重复计数。
- 答题：每题首次确认结果，区分 found 与 revealed。完成一轮包括揭晓答案，但不包括内容删除导致的结束，也不表示已掌握。
- 历史查看：实际打开已保存照片详情，包括首页／相册与单词照片入口；不是列表曝光。
- 主动听词：用户主动触发单词播放并收到系统 didStart 回调；自动播放和例句播放不计入。
- 设备列表学习次数：识别成功次数 + 答题次数 + 主动听词次数。这是行为次数，不是独立单词数。

## 数据覆盖与存储

识别沿用服务端既有记录，以请求开始时的北京时间日期归属识别尝试及成功次数，客户端不能上报识别计数。新客户端行为从迁移 008 的启用时间开始；旧版和离线未补传的数据不能还原。界面显示数据覆盖提示；启用前的访问／打开，以及只有历史识别的设备打开次数，显示“未覆盖”。新行为不上传照片、单词正文、音频、原始页面内容。

事件在 iOS Application Support 本地持久化，成功确认后移除；失败以 30 秒起、最长 5 分钟的间隔重试，重新进入前台也会尝试。一次最多 100 条。发生时间、事件 ID、轮次 ID 和当时环境在重试时保持不变。首次启动的环境查询完成前暂不上报；无法确认环境时保留为 Unknown。

服务端在同一事务内按事件 ID 去重并更新每日汇总。只确认成功写入的批次；超过最近 90 个北京时间日期、或领先服务器超过 5 分钟的事件确认后丢弃，不进入统计，以免异常本地时钟阻塞队列。请求校验失败和服务端故障不确认事件。

行为明细与既有识别明细一样保留最近 90 天；每日汇总长期保留。服务启动及每日维护时分批清理，重试已过期事件不会重建明细或重复汇总。环境以事件发生时的值为准，不以设备当前环境重算历史。

## 接口与上线

- `POST /v1/activity/events`：沿用 App Bearer 鉴权，服务端从凭据确定设备。请求 `{ events: [...] }`，事件包含 `eventId`、ISO 8601 `occurredAt`、`eventName`、`environment`，可带 `sessionId`、`outcome`、`appVersion`、`appBuild`。听音找词开始／答题／完成必须带轮次 ID，只有答题可以且必须带 found／revealed 结果。
- 成功响应 `{ acknowledgedEventIds: [...] }`；客户端仅删除本批次内已确认 ID。
- `GET /admin/api/stats`：增加 `activity` 概览与设备活跃汇总。设备范围包括所选期间有行为或新注册的设备；安装新增指标仍按注册日期单独计算。
- `GET /admin/api/stats/devices/:installationId/activity`：支持 `startDate`、`endDate`、`environment` 与分页 `cursor`；明细每页 50 条，汇总不受分页影响。识别详情仍使用原接口，并新增可选环境筛选。

上线顺序：先通过 `server/` 下的 `npm run db:migrate` 应用迁移，再部署 API，最后发布新版 iOS。旧客户端和原付费事件接口保持兼容；新客户端遇到旧服务端时保留队列，待服务端可用再上传。本次本地实现不对任何生产数据库执行迁移或部署。

## 验证

`npm test` 包含活跃接口、汇总口径和管理后台测试；`npm run test:postgres` 包含事务回滚、并发去重、北京时间边界、老设备回访、环境、分页与过期清理测试，需要独立的 TEST_DATABASE_URL。

iOS 的 ActivityTrackerTests 和 WordLearningStoreTests 覆盖短暂返回／30 分钟返回、跨午夜、离线持久化、分批确认、环境冻结、练习恢复／重复完成、空状态／删除内容、主动播放实际开始等行为。
