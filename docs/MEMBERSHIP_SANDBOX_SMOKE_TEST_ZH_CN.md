# 会员 Sandbox 快速冒烟测试

适用范围：咔咔单词 iOS 真机 + App Store Sandbox。

目标：在约 10–15 分钟内确认商品展示、购买验签、会员权益、恢复购买和订阅管理闭环可用。

## 0. 测试前确认

- [ ] 使用真机，不使用 Xcode StoreKit 本地交易。
- [ ] 当前 Scheme 的 `StoreKit Configuration` 为 `None`。
- [ ] 使用未消耗免费额度的设备，启动后设置页显示“免费版”和 `3/3`。
- [ ] 客户端和服务端 Bundle ID 均为 `com.kakaword.app`。
- [ ] 商品 ID 一致：
  - 月会员：`com.kakaword.app.membership.month`
  - 年会员：`com.kakaword.app.membership.annual`
- [ ] 真机与服务端在同一局域网；当前客户端 API 地址为 `http://192.168.0.108:8787`。
- [ ] 服务端已执行数据库迁移，健康检查通过：

  ```bash
  curl -fsS http://192.168.0.108:8787/health
  ```

- [ ] Sandbox 服务端使用 `DEVICECHECK_ENVIRONMENT=development`，Apple Root CA、App ID、DeviceCheck 密钥均已配置。
- [ ] 若验证订阅通知，`/v1/store/notifications` 已通过公网 HTTPS 暴露；购买同步本身依赖 `/v1/store/sync`。

> 工程内的 `ios/KakawordSubscriptions.storekit` 仅用于本地 StoreKit 测试。本轮使用真实 Sandbox 时不要让它接管交易，否则 Debug 客户端会将 Xcode 交易直接视为本地会员，不会验证服务端。

服务端验收应满足：

```text

productId = com.kakaword.app.membership.annual

```

如有数据库访问权限，可用以下只读查询确认最近交易；不要把交易 ID 或签名内容放进截图或反馈消息：

```sql

FROM picture_word_subscriptions
ORDER BY updated_at DESC
LIMIT 5;
```

## 7. 失败定位顺序

1. 商品不显示：确认 Scheme 未使用本地 StoreKit、Bundle ID 和两个商品 ID 正确。
2. 购买成功但仍是免费版：检查 `/v1/store/sync`、Apple Root CA、Apple App ID、Sandbox 环境和服务端数据库。
3. 会员生效但识别失败：检查 API 地址、服务端数据库、DeviceCheck 和视觉模型服务。
4. 恢复失败：确认使用同一个 Sandbox 账号，等待交易状态同步后再试。
5. 原识别没有自动重试：重点检查从额度拦截进入会员页后的购买完成回调。

## 8. 本轮明确不测

退款、撤销、账单宽限期、月/年切换、100 次额度耗尽、跨月重置、并发识别和 10 分钟预占过期，统一放入第二轮回归测试。

## 10. 产品与合规记录

### MBR-POLICY-001：是否仅在 Debug 显示“管理订阅”

- 结论：不建议仅在 Debug 显示；生产环境应保留有效会员的“管理订阅”入口。
- 当前行为：免费用户不显示该入口；有效会员显示入口，并调用 StoreKit 的系统订阅管理界面，符合当前产品实现。
- 原因：Apple 没有明确要求必须自建一个管理页面，但官方建议让用户容易进入系统提供的订阅管理 UI。隐藏生产入口会增加取消订阅的阻力，带来审核和用户体验风险。
- 测试要求：有效会员在设置页能打开 Apple 订阅管理；关闭自动续订后，当前付费期内会员权益仍然保留。

### MBR-POLICY-002：取消自动续订后的会员展示

- 结论：取消自动续订后，在 `expiresAt` 到期前继续展示会员信息，不提前切换为“开通会员”。
- 当前实现：`isMember` 对 `active` 和 `grace` 都返回 true；服务端只在订阅过期、撤销或宽限期结束后恢复免费状态。
- 预期界面：继续显示当前会员方案、剩余额度和到期/重置信息；可继续使用会员权益，同时保留“管理订阅”入口。到期后再显示“开通会员”。
- 依据：关闭自动续订只是取消下一周期续费，用户仍可使用当前周期权益。[Apple 订阅取消说明](https://developer.apple.com/documentation/advancedcommerceapi/cancel-a-subscription)

### MBR-POLICY-003：非会员状态是否显示“恢复购买”

- 结论：应显示。免费用户也可能是在新设备、重装 App、服务端同步失败或本地状态丢失后尝试恢复已有订阅。
- 当前实现：设置页和会员页均提供“恢复购买”，符合恢复可恢复内购的要求。
- 预期行为：有有效购买记录时恢复会员；没有购买记录时提示“没有找到可恢复的有效会员”，不能误开通会员。
- 依据：Apple 要求可恢复的 App 内购买提供恢复机制，并建议提供 Restore Purchases 按钮。[Apple 恢复购买说明](https://developer.apple.com/documentation/storekit/restoring-purchased-products)

### MBR-POLICY-004：有效会员额度用尽时仍可能看到订阅购买按钮

- 发现日期：2026-08-28
- 修复状态：会员页已按有效会员状态隐藏套餐和购买按钮，仅显示额度重置说明与“管理订阅”；购买方法也会在调用 Apple 前再次校验权益。
- 严重程度：中高；可能造成用户误操作换购或重复发起购买
- 预期规则：只有非会员、已到期或已撤销状态显示“开通会员”；有效 `active`/`grace` 会员，即使本期额度为 0，也只显示额度耗尽说明和“管理订阅”。
- 当前设置页：根据 `membership.isMember` 在“管理订阅”和“开通会员”之间切换，行为正确。
- 修复前风险：`HomeView` 和 `ResultView` 根据 `canStartRecognition` 判断是否打开会员页；有效会员额度为 0 时，会进入包含购买按钮的 `PaywallView`。购买动作也没有额外检查 `membership.isMember`。
- 重复购买处理：两个产品在同一订阅组、同一等级，Apple 不会让用户同时持有同组的两份有效订阅；月/年选择会被 Apple 作为换购/套餐变更处理。服务端以 `(environment, original_transaction_id)` 唯一标识订阅，并通过幂等 upsert 和较新的 `purchase_at` 防止重复或旧交易覆盖新状态。
- 建议修复：额度耗尽时区分“会员但额度用尽”和“免费额度用尽”；前者不进入购买页，或在购买页隐藏购买按钮并只提供“管理订阅”。发起购买前再次读取会员状态，防止缓存状态导致误购买。
- 依据：Apple 订阅组同一时间只能持有一个组内订阅，用户可在组内进行升级、降级或换购。[Apple 自动续期订阅说明](https://developer.apple.com/app-store/subscriptions/)

### MBR-POLICY-005：换设备后未点击恢复购买就直接购买

- 结论：有效订阅应优先由 StoreKit 自动发现并同步，不应要求用户必须先点击“恢复购买”。手动恢复是自动同步失败时的兜底入口。
- 修复状态：权益加载/刷新期间购买按钮保持禁用；购买前强制同步 `Transaction.currentEntitlements` 和服务端状态，发现有效会员时不再打开 Apple 购买确认页。
- 当前实现：新设备启动时执行 `Transaction.currentEntitlements`；发现有效月/年会员后调用 `/v1/store/sync`，服务端按相同的 `environment + originalTransactionId` 绑定新设备。
- 预期结果：新设备直接显示原会员身份，并共享原订阅月的额度，不重新赠送一份 `100` 次额度。
- 修复前风险：如果用户在自动同步完成前进入购买页，购买动作没有再次检查 `membership.isMember`。Apple 同一订阅组不会形成两份并行有效订阅，但可能进入换购或重复交易处理，客户端不应依赖 Apple 的拦截结果。
- 建议修复：加载中或会员状态未知时禁用“开通会员”；发起购买前重新刷新会员状态；确认有效会员后只显示“管理订阅”。
- 依据：StoreKit 在新设备或重装后可通过 `currentEntitlements` 提供当前有效交易，通常不需要用户主动恢复。[Apple StoreKit sync() 说明](https://developer.apple.com/documentation/storekit/appstore/sync%28%29)

## 9. 已发现问题

### MBR-SBX-001：购买记录找到，但会员同步时连接断开

- 发现日期：2026-08-28
- 修复状态：客户端已增加幂等重试、延长同步超时并携带请求 ID；等待真机 Sandbox 回归确认。
- 严重程度：高；阻断购买后的会员开通
- 测试步骤：Sandbox 购买会员成功后进入设置页，等待会员状态同步。
- 实际结果：提示“购买已找到，但同步失败：The network connection was lost.”
- 预期结果：`/v1/store/sync` 返回成功，设置页显示有效会员和 `100/100` 额度。
- 初步定位：StoreKit 已在 `Transaction.currentEntitlements` 找到已验证交易，但客户端调用 `POST /v1/store/sync` 时连接在返回 HTTP 响应前断开。由于请求没有得到正常响应，当前不能确认服务端是否已经写入订阅。
- 影响：会员可能仍显示免费版；交易未执行 `finish()`，后续启动或恢复购买可能再次尝试同步。

最短排查顺序：

1. 在真机同一网络打开 `http://192.168.0.108:8787/health`，确认客户端实际能访问开发服务器。
2. 购买发生时查看服务端日志：确认是否出现 `/v1/store/sync` 的完成日志；若没有，优先检查 Wi-Fi、Mac 防火墙、服务端进程和局域网 IP 是否变化。
3. 若有请求日志但没有完成日志，检查服务端数据库连接、Apple JWS 在线验签请求和进程是否在处理期间崩溃或被反向代理断开。
4. 若服务端已成功写入订阅，重新打开 App 或点击“恢复购买”确认客户端能读取会员状态，避免重复购买。

### MBR-UI-001：恢复购买缺少 loading 状态

- 发现日期：2026-08-28
- 修复状态：设置页和会员页已统一增加恢复中进度、文案及重复操作禁用；等待真机回归确认。
- 严重程度：中；影响操作反馈，不直接影响恢复逻辑
- 复现步骤：在设置页或会员页点击“恢复购买”，等待 StoreKit 同步完成。
- 实际结果：按钮仍显示“恢复购买”，看不到进度或“正在恢复”提示；设置页按钮仅被禁用，会员页还可能继续响应重复点击。
- 预期结果：点击后立即显示明确的恢复中状态，恢复期间禁止重复操作；成功或失败后恢复正常按钮状态并显示结果提示。
- 初步定位：`MembershipStore.restorePurchases()` 已维护 `isPurchasing` 状态，但设置页没有将状态映射为 loading 文案/进度，`PaywallView` 的恢复按钮也没有使用该状态禁用或展示进度。
- 建议修复：设置页和会员页统一显示 `ProgressView` + “正在恢复购买…”；恢复期间禁用恢复按钮和购买按钮，完成后沿用现有“购买记录已恢复 / 没有找到可恢复的有效会员 / 错误信息”提示。
