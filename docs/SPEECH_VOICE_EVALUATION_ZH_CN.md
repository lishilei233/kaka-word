# 英语发音音色方案评估

## 结论

当前版本采用 iOS 系统 `AVSpeechSynthesizer`，向用户提供设备上实际可用的美式英语和英式英语音色。AI 语音暂不接入，待服务商、预算、会员规则、文本保留政策和授权范围明确后再单独立项。

系统方案已经覆盖本产品高频的单词、例句和短描述朗读，并具备低延迟、可离线、无需新增凭证及运行费用的优势。不同设备安装的音色可能不同，因此产品只保存 voice identifier，并始终提供系统默认回退。

## 方案比较

| 维度 | iOS 系统语音 | AI 语音 |
| --- | --- | --- |
| 自然度与准确性 | 系统增强或优质音色可满足短句学习；质量随设备资源而异 | 通常更自然，也可能提供语气和风格控制；仍需逐词校验学习场景准确性 |
| 口音 | 可使用设备已有的美式、英式及其他地区英语 | 可由服务商提供稳定的固定口音，但具体覆盖依赖模型 |
| 首播延迟 | 本地合成，通常可以立即开始 | 包含网络、服务排队、合成和音频下载延迟 |
| 离线能力 | 已安装音色可离线使用 | 通常需要网络；离线需预生成和缓存 |
| 设备兼容性 | 由 iOS 管理；可用名称和质量因系统版本、地区及下载资源不同 | 客户端播放较一致，但需要维护网络与音频格式兼容 |
| 费用 | 无按次 API 成本 | 按字符、时长或请求付费，还会产生代理和存储流量成本 |
| 隐私 | 文本留在系统语音链路，不需要发送至应用服务端 | 必须把单词或例句发送给第三方，需要披露处理者、用途与保留期限 |
| 授权 | 使用系统公开 API，应用不分发独立音频资产 | 必须确认生成音频在商业 App、缓存和再次播放场景中的授权 |
| 稳定性 | 不依赖应用服务器；系统音色被移除时需要回退 | 受网络、限流、供应商故障和 API 变更影响，必须回退到系统语音 |
| 维护成本 | 维护音色筛选、展示、持久化和失效回退 | 还需维护服务端代理、密钥、限流、缓存、监控、账单和供应商升级 |

## 本期产品规则

- 从 `AVSpeechSynthesisVoice.speechVoices()` 当前返回的音色中精选最多 3 个 `en-US` 与 2 个 `en-GB` 常规音色，不触发资源下载；过滤系统标记的趣味音色和私人声音，一侧不足时由另一侧补位。
- 设置页主卡片只显示当前音色摘要；点击后使用纸张风格 Sheet 展示“系统默认”和最多 5 个具名音色，并用音色名称、口音和质量说明区分选项，不向用户展示内部 identifier。
- Sheet 中点击整行只选择音色，每行右侧的播放按钮独立试听固定英文示例句，避免选择时意外发声；关闭 Sheet 时停止试听。
- 空 identifier 表示“系统默认”；用户选择仅保存在当前设备的 `UserDefaults`。
- 已选音色不可用时，依次尝试当前地区匹配的系统英语默认音色、另一目标口音默认音色、任一目标口音音色，最后尝试任一系统英语音色。
- 新播放和切换音色都会立即停止当前朗读，避免旧音色继续播放或请求排队。
- 系统可用音色发生变化时立即刷新精选列表；已选音色不再可用时恢复“系统默认”。

## AI 语音后续准入条件

只有在真机对比确认系统音色无法满足自然度或教学准确性后，才进入 AI 语音开发。立项前必须明确供应商和模型、逐字符成本与预算上限、免费或会员权益、服务端代理与密钥管理、超时及限流、文本和音频保留期限、商业授权、隐私政策更新、缓存清理和系统语音降级策略。
