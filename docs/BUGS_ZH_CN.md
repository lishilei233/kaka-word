# Bug 记录

## BUG-001：服务端异常或无网络时设置页持续显示读取额度

- 严重程度：P1
- 触发条件：服务端异常或设备无网络时打开设置页。
- 实际结果：页面一直显示“正在读取识别额度”，没有结束 loading 或错误提示。
- 预期结果：请求失败后停止 loading，并显示明确的网络或服务暂不可用提示。
- 影响：用户无法确认当前额度或会员状态。
- 初步排查方向：会员额度请求失败后的 loading 状态未在异常分支重置。

## BUG-002：删除并重新安装 App 后会员权益无法恢复

- 严重程度：P0，订阅发布阻断
- 复现步骤：购买会员，删除 App，重新安装，然后点击“恢复购买”。
- 实际结果：会员状态丢失，并提示“没有找到可恢复的有效会员”。
- 预期结果：使用同一 Apple ID 重新安装后自动恢复会员；手动恢复购买也应成功。
- 影响：已付费用户无法使用会员功能。
- 初步排查方向：
  - StoreKit `currentEntitlements` 是否发现原交易。
  - `/v1/store/sync` 是否成功调用并绑定原始交易。
  - 服务端是否按 `environment + originalTransactionId` 正确保存会员。
  - 新安装生成的新设备凭证是否正确关联到原订阅。

## BUG-003：购买成功后会员权益未生效，仍被识别额度拦截

- 严重程度：P0，订阅发布阻断
- 场景一：首页点击拍摄，进入购买会员流程并购买成功；拍照后仍提示购买会员，以及“免费识别次数已用完，开通会员后可继续识别”。
- 场景二：在设置页开通会员成功后，状态仍显示“免费版”。
- 补充情况：购买月会员后可以正常使用，会员状态和识别权益均能生效；当前问题可能只出现在特定商品或特定购买入口，具体范围待进一步确认。
- 实际结果：购买完成后客户端权益没有更新，识别仍按免费用户处理。
- 预期结果：购买成功并同步后立即显示会员状态，并允许继续拍照识别。
- 影响：用户已付款但无法使用会员权益。
- 初步排查方向：
  - StoreKit 购买完成后的交易同步是否成功。
  - `/v1/store/sync` 是否返回成功。
  - `MembershipStore.entitlement` 是否更新并发布权益变更通知。
  - 购买完成后的页面是否重新刷新权益。
  - 网络异常是否导致 Apple 购买成功但服务端同步失败。

## 关联关系

BUG-002 与 BUG-003 高度相关，优先作为同一条“订阅交易同步与客户端权益刷新”链路联合排查。BUG-001 也可能暴露同一模块在网络失败时未正确结束 loading 的问题。

## BUG-004：直接修改 `free_used` 后免费额度会被 DeviceCheck 恢复

- 严重程度：P1，阻塞免费额度手动测试
- 触发条件：在数据库中将某安装记录的 `free_used` 修改为 `0`，等待一段时间或重新触发启动/识别流程。
- 实际结果：`free_used` 又变回 `3`，无法通过数据库调整免费额度进行测试。
- 预期结果：测试环境应提供可控的免费额度重置方式；至少在明确的测试配置下，数据库修改不应被后台状态静默覆盖。
- 影响：无法快速复现免费额度 `3/3`、`1/3`、`0/3` 及第四次识别拦截场景。
- 已定位原因：
  - `bootstrap` 会读取 DeviceCheck 两位状态，并用 `GREATEST(数据库 free_used, DeviceCheck 已用次数)` 写回数据库。
  - 免费识别预占流程也会用 `GREATEST(free_used, DeviceCheck 已用次数)` 更新数据库。
  - 因此 DeviceCheck 仍为 `3` 时，单独把数据库改为 `0` 会在下一次相关请求中恢复为 `3`。
- 测试建议：为 Sandbox/本地测试提供明确的额度重置工具或可注入的 DeviceCheck mock，避免直接修改生产额度数据。

## BUG-005：ResultView 照片上的单词标签仍会重叠

- 严重程度：P1，影响核心识别结果阅读
- 触发条件：在 ResultView 查看包含多个识别物体的照片。
- 实际结果：照片上的英文单词标签仍存在相互重叠，影响单词辨认和引导线对应关系。
- 预期结果：标签之间保持可读间距；即使物体集中在同一区域，也能通过布局调整或引导线清晰对应到目标物体。
- 当前状态：代码已修复，待真机回归。自动布局和手动拖动都以 4pt 安全间距作为硬约束；空间不足时宁可省略无法安全放置的标签，也不会让单词互相遮挡。引导线无法绕开其他标签时同样省略，不允许穿过单词。
- 重点验证场景：
  - 多物体且标签较长。
  - 物体集中在照片边缘或中心区域。
  - 竖图、横图和小屏设备。
  - Dynamic Type 大字号和不同缩放比例。
- 初步排查方向：`AnnotationLayoutEngine` 的标签避让、边界约束、最小间距和标签位置覆盖逻辑。

## BUG-006：会员购买后原有年/月会员取消，错误提示本期额度已用完

- 严重程度：P0，订阅权益与额度状态异常
- 触发条件：购买会员成功后，原有年会员或月会员发生取消/切换。
- 实际结果：出现“本期识别额度已用完”的提示。
- 预期结果：订阅切换或旧订阅取消后，应根据当前有效订阅、当前订阅周期和实际已用额度展示正确状态；不能因旧交易取消而错误显示额度耗尽。
- 当前状态：待定位。
- 补充信息待确认：这里的“取消”是用户主动关闭自动续订、月/年套餐切换，还是购买成功后旧交易状态被服务端更新为取消。
- 初步排查方向：
  - App Store 交易更新中旧交易与新交易的先后顺序。
  - 服务端按 `environment + originalTransactionId` 更新订阅状态时是否错误覆盖了当前有效订阅。
  - 当前订阅周期的 `used_count`、`reserved_count` 和 `quota_limit` 是否关联到了旧订阅。
  - 客户端收到订阅状态变化后是否刷新了错误的 entitlement。

## BUG-007：StoreKit 交易更新可能被刷新竞态静默丢弃

- 严重程度：P1，可能导致会员状态陈旧
- 触发条件：StoreKit 收到续订、退款、撤销或 Ask to Buy 批准等交易更新，同时 App 正在加载、购买或执行另一次会员状态刷新。
- 实际结果：交易监听没有直接处理收到的交易，而是触发全量刷新；如果刷新方法发现已有加载/购买/刷新任务，会直接返回，当前交易可能没有被补处理。
- 影响：会员状态可能保持陈旧，直到下一次进入前台或手动刷新。
- 预期结果：交易更新不应因并发刷新被丢弃；当前任务结束后应自动补跑一次同步，确保最终状态与 StoreKit 和服务端一致。
- 当前状态：待修复。
- 初步排查方向：`MembershipStore.refreshCurrentEntitlements` 的互斥 guard 与 `listenForTransactions` 的调用关系。
- 建议方案：增加 `pending`/`dirty` 标记；当刷新、购买或加载期间收到交易更新时记录待处理状态，并在当前任务结束后补跑一次交易同步。

## BUG-008：付费墙“推荐 · 省 40%”文案固定写死，可能与本地价格不符

- 严重程度：P2，价格展示准确性问题
- 触发条件：在非中国大陆 App Store 店面查看付费墙。
- 实际结果：付费墙固定显示“推荐 · 省 40%”，但月会员和年会员的 StoreKit 本地价格比例可能并非 40%。
- 预期结果：折扣文案应根据两个产品的实际本地价格动态计算；如果无法可靠计算，则只显示“推荐”，不展示固定折扣比例。
- 影响：海外用户可能看到不准确的价格优惠信息，造成误解或审核风险。
- 初步排查方向：`PaywallView.swift` 中推荐标签的固定文案，以及 `Product.displayPrice` 在不同店面、税费和货币下的解析方式。
- 建议方案：优先使用 StoreKit 提供的实际价格计算折扣；若计算结果不可靠，统一降级为“推荐”。
